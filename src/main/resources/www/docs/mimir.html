Mimir is the database access component used across the app. It wraps a JDBC connector and provides small, explicit helpers for queries, mapping, pagination, and transactions.

1) Connectors and Initialization

Mimir works with a pluggable connector interface DbConnector and a default SQLite/Hikari implementation Verdandi.

  • DbConnector — contract for DB lifecycle and connections:
    initialize(), isReady(), getReaderConnection(), getWriterConnection(), withTransaction(Function<Connection,T>), close().
    See: org.ruitx.jaws.components.mimir.DbConnector
  • Verdandi — SQLite connector using Hikari pools (reader/writer), applies PRAGMAs, and initializes schema. See: org.ruitx.jaws.components.mimir.Verdandi

2) Database Configuration

Databases are configured via DatabaseConfig and registered with Odin. Fields:

public record DatabaseConfig(
    String databasePath,
    String schemaPath,
    int readerPoolSize,
    int busyTimeoutMs,
    boolean enableWal,
    String synchronousMode,
    Long leakDetectionThresholdMs,
    String writerPoolName,
    String readerPoolName,
    List<DatabaseSeeder> seeders
) {}

Default databases are registered in Odin:

// org.ruitx.jaws.components.Odin.registerDefaultDatabases()
registerDatabase("db", new DatabaseConfig(
    ApplicationConfig.DATABASE_PATH,
    ApplicationConfig.DATABASE_SCHEMA_PATH,
    ApplicationConfig.MIMIR_READER_POOL_SIZE,
    ApplicationConfig.MIMIR_BUSY_TIMEOUT_MS,
    ApplicationConfig.MIMIR_ENABLE_WAL,
    ApplicationConfig.MIMIR_SYNCHRONOUS_MODE,
    null,
    "jaws-writer",
    "jaws-reader",
    List.of(/* seeders */)
));

registerDatabase("logs", new DatabaseConfig(
    Paths.get("src/main/resources/logs.db").toString(),
    Paths.get("src/main/resources/sql/logs_schema_v1.sql").toString(),
    Math.max(2, ApplicationConfig.MIMIR_READER_POOL_SIZE / 2),
    ApplicationConfig.MIMIR_BUSY_TIMEOUT_MS,
    true,
    ApplicationConfig.MIMIR_SYNCHRONOUS_MODE,
    null,
    "jaws-logs-writer",
    "jaws-logs-reader",
    null
));

Access registered DBs via Odin.getDB() or Odin.getDB("logs").

2.1) Environment Variables

These environment variables (or corresponding properties) control Mimir and database behavior. See org.ruitx.jaws.configs.ApplicationConfig.

// Paths
DBPATH=src/main/resources/db.db
DBSCHEMAPATH=src/main/resources/sql/db_schema_v1.sql

// Connection/pooling & SQLite pragmas
MIMIR_READER_POOL_SIZE=16
MIMIR_BUSY_TIMEOUT_MS=5000
MIMIR_ENABLE_WAL=true
MIMIR_SYNCHRONOUS_MODE=NORMAL

// Startup barrier (Odin waits for DB readiness)
STARTUP_DB_TIMEOUT_MS=30000

// Query cache
MIMIR_CACHE_ENABLED=true
MIMIR_CACHE_MAX_SIZE=10000
Values can also be provided via src/main/resources/application.properties using matching keys (e.g., database.path, database.schema.path, mimir.cache.enabled, etc.).

2.2) Seeders (Database bootstrap)

Seeders run after a database is initialized and ready. They must be idempotent. If any seeder throws, startup aborts.

  • Interface: org.ruitx.jaws.components.mimir.DatabaseSeeder with name() and run(Mimir db).
  • Attach: pass a list to DatabaseConfig.seeders() when registering the DB in Odin.registerDatabase(...).
  • Execution: Odin wraps each seeder in a transaction (begin/commit/rollback) and logs times. 
// Define a seeder
package org.example.db.seeders;

import java.util.Optional;
import org.ruitx.jaws.components.mimir.Mimir;
import org.ruitx.jaws.components.mimir.DatabaseSeeder;

public class ExampleSeeder implements DatabaseSeeder {
  public String name() { return "ExampleSeeder"; }
  public void run(Mimir db) throws Exception {
    // idempotent logic: check, then create
    Optional<org.ruitx.jaws.types.Row> row = db.getRow("SELECT id FROM MY_TABLE WHERE name=?", "default");
    if (row.isEmpty()) {
      db.execute("INSERT INTO MY_TABLE(name) VALUES (?)", "default");
    }
  }
}

// Register database with seeders (in Odin or your bootstrap)
Odin.registerDatabase("db", new DatabaseConfig(
    ApplicationConfig.DATABASE_PATH,
    ApplicationConfig.DATABASE_SCHEMA_PATH,
    ApplicationConfig.MIMIR_READER_POOL_SIZE,
    ApplicationConfig.MIMIR_BUSY_TIMEOUT_MS,
    ApplicationConfig.MIMIR_ENABLE_WAL,
    ApplicationConfig.MIMIR_SYNCHRONOUS_MODE,
    null,
    "jaws-writer",
    "jaws-reader",
    java.util.List.of(
        new org.ruitx.jaws.components.mimir.defaultSeeders.AdminBootstrapSeeder(),
        new org.example.db.seeders.ExampleSeeder()
    )
));
See org.ruitx.jaws.components.Odin.registerDatabase() for the transaction wrapper and logging. Example included seeder: AdminBootstrapSeeder ensures an admin role/user exists.

3) Repository Helpers

Extend Repository for typed access with small, explicit helpers.

// org.ruitx.jaws.components.mimir.Repository
protected <T> Optional<T> getOne(String sql, RowMapper<T> mapper, Object... params)
protected <T> List<T>     getAll(String sql, RowMapper<T> mapper, Object... params)
protected <T> Page<T>     getPage(String sql, PageRequest pr, RowMapper<T> mapper, Object... params)
protected int             execute(String sql, Object... params)
protected long            insert(String sql, Object... params)
protected <R> R           inTransaction(SqlSupplier<R> body) throws Exception
protected void            inTransaction(SqlRunnable body) throws Exception

Examples from real repositories:

// org.ruitx.www.base.repository.AuthRepo
@Cacheable(tables = {"USER"})
public Optional<User> getUserByUsername(String username) {
  return getOne("SELECT * FROM USER WHERE user = ?", UserMapper.INSTANCE, username);
}

// Lightweight projection using RowBinder
public List<UserSummaryProjection> listUserSummaries() {
  String sql = """
      SELECT id AS id, user AS user, first_name AS firstName, last_name AS lastName
      FROM USER ORDER BY created_at DESC
      """;
  return getAll(sql, RowBinder.mapper(UserSummaryProjection.class));
}

3.1) Repository Skeleton

Start with a simple repository that extends Repository. Inject Mimir or use the default DB via Odin.getDB().

package org.example.app.repository;

import java.util.List;
import java.util.Optional;
import org.ruitx.jaws.components.Odin;
import org.ruitx.jaws.components.mimir.Mimir;
import org.ruitx.jaws.components.mimir.Repository;
import org.ruitx.jaws.components.mimir.RowBinder;
import org.ruitx.jaws.components.mimir.RowMapper;
import org.ruitx.jaws.types.Page;
import org.ruitx.jaws.types.PageRequest;
import org.ruitx.jaws.interfaces.Transactional;
import org.ruitx.jaws.interfaces.IsolationLevel;

public class ExampleRepo extends Repository {
  public ExampleRepo() { this(Odin.getDB()); }
  public ExampleRepo(Mimir db) { super(db); }

  // Typed mapper (could be a separate mapper class)
  private static final RowMapper<MyEntity> MY_ENTITY = r -> new MyEntity(
      r.getLong("id").orElse(null),
      r.getString("name").orElse("")
  );

  public Optional<MyEntity> findById(Long id) {
    return getOne("SELECT * FROM MY_TABLE WHERE id = ?", MY_ENTITY, id);
  }

  public List<MyEntity> listAll() {
    return getAll("SELECT * FROM MY_TABLE ORDER BY created_at DESC", MY_ENTITY);
  }

  // Projection example using RowBinder
  public List<MyProjection> listSummaries() {
    String sql = "SELECT id AS id, name AS name FROM MY_TABLE";
    return getAll(sql, RowBinder.mapper(MyProjection.class));
  }

  // Pagination
  public Page<MyEntity> page(PageRequest pr) {
    return getPage("SELECT * FROM MY_TABLE ORDER BY id DESC", pr, MY_ENTITY);
  }

  // Writes in a transaction (annotation-based)
  @Transactional(isolation = IsolationLevel.SERIALIZABLE, readOnly = false)
  public int deactivateAndLog(Long id) throws Exception {
    int a = execute("UPDATE MY_TABLE SET active = 0 WHERE id = ?", id);
    int b = execute("INSERT INTO AUDIT(entity_id, action) VALUES (?, ?)", id, "DEACTIVATE");
    return a + b;
  }
}

// Example projection record (prefer Optional fields for nullable columns)
public record MyProjection(java.util.Optional<Long> id, java.util.Optional<String> name) {}

// Example entity (simplified)
public record MyEntity(Long id, String name) {}

4) Row Mapping

  • RowMapper<T> — functional interface for explicit mapping.
    T map(Row r) throws Exception;
  • RowBinder — reflection-based binder for lightweight projections (records/POJOs). Prefer Java records, alias SQL columns to projection names, and use Optional<T> for nullable fields. 
// org.ruitx.jaws.components.mimir.RowMapper
@FunctionalInterface
public interface RowMapper<T> { T map(Row r) throws Exception; }

// RowBinder projection example
public record UserSummaryProjection(
    Optional<Long> id,
    Optional<String> user,
    Optional<String> firstName,
    Optional<String> lastName
) {}

String sql = """
  SELECT id AS id, user AS user, first_name AS firstName, last_name AS lastName
  FROM USER ORDER BY created_at DESC
""";
List<UserSummaryProjection> rows = repo.getAll(sql, RowBinder.mapper(UserSummaryProjection.class));
RowBinder Notes:
  • Case-insensitive column matching; alias to match record component or POJO property names.
  • Optional<T> fields are filled with Optional.of(value) or Optional.empty().
  • Common conversions supported (Integer/Long, Float/Double, numeric<->boolean, String parsing).
  • Intended for flat projections and small DTOs; use custom mappers for complex entities.

5) Pagination

Use Mimir.getPage (or Repository.getPage) with PageRequest and a mapper.

// From BackofficeRepo (logs DB)
Page<LogEntry> entryPage = logsDb.getPage(
    "SELECT id, timestamp, level, message, logger FROM LOG_ENTRIES ORDER BY timestamp DESC",
    pageRequest,
    LogEntryMapper.INSTANCE::map
);

6) Transactions

Wrap write sequences in a transaction. Repositories expose inTransaction helpers:

return inTransaction(() -> {
  int a = execute("UPDATE USER SET is_active = 0 WHERE id = ?", userId);
  int b = execute("UPDATE USER_SESSION SET is_active = 0 WHERE user_id = ?", userId);
  return a + b;
});

You can also manage transactions directly on Mimir (beginTransaction(), commitTransaction(), rollbackTransaction()).

7) Multiple Databases

The application uses a main DB and a dedicated logs DB. Access by alias:

Mimir db = Odin.getDB();           // default "db"
Mimir logsDb = Odin.getDB("logs"); // logs database

8) Caching

Repositories use @Cacheable(tables = { ... }) to mark query methods as cacheable. See usages in AuthRepo and BackofficeRepo for examples.

9) Basic Read/Write Examples

// Read rows as generic Row
List<Row> rows = db.getRows("SELECT * FROM USER WHERE is_active = 1");

// Insert/Update/Delete
int updated = db.execute("UPDATE USER SET last_login = ? WHERE id = ?", Instant.now(), userId);
long newId = db.insert("INSERT INTO TODO (todo) VALUES (?)", todoText);

// Typed read with mapper
typedef RowMapper<User> mapper = UserMapper.INSTANCE;
Optional<User> user = repo.getOne("SELECT * FROM USER WHERE id = ?", mapper, id);
List<User> all = repo.getAll("SELECT * FROM USER ORDER BY created_at DESC", mapper);
Keep mappings explicit and simple. Prefer Optional-returning reads and projection records for lists.
