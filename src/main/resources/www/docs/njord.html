You can create dynamic routes by creating a controller class that extends Bragi and annotating its methods with the @Route annotation. Common attributes are endpoint, method, responseType, and optional htmx.

Dynamic Routes

The endpoint represents the path that the method will respond to. Dynamic segments are prefixed with :. Example: /todos/:id. Below is an example aligned with the current codebase patterns:

import static org.ruitx.jaws.strings.RequestType.GET;
import static org.ruitx.jaws.strings.ResponseCode.OK;
import static org.ruitx.jaws.strings.ResponseType.HTML;
import static org.ruitx.jaws.types.ParamType.PATH;

import org.ruitx.jaws.interfaces.Route;
import org.ruitx.jaws.interfaces.AccessControl;

@AccessControl(login = true)
@Route(endpoint = "/backoffice/logs/:id", method = GET, responseType = HTML)
public void renderLogDetail() {
    String logId = get("id", PATH);
    if (logId == null) {
        sendFail(BAD_REQUEST, "Log ID is required.");
        return;
    }

    sendHTML(OK, render("backoffice/log-detail.html", backofficeService.getLogDetailContext(logId)));
}

Path & Query Parameters

In dynamic routes, a segment like :id is extracted with get("id", PATH). For example, for /backoffice/logs/25, get("id", PATH) returns "25".

Query parameters are read with get(name, QUERY) and should be parsed/validated as needed:

import static org.ruitx.jaws.types.ParamType.QUERY;

@Route(endpoint = "/backoffice/htmx/logs", method = GET, responseType = HTML, htmx = true)
public void getPaginatedLogTable() {
    int page = 0;
    int size = 10;

    String pageParam = get("page", QUERY);
    if (pageParam != null) {
        try { page = Integer.parseInt(pageParam); } catch (NumberFormatException ignored) {}
    }

    String sizeParam = get("size", QUERY);
    if (sizeParam != null) {
        try { size = Integer.parseInt(sizeParam); } catch (NumberFormatException ignored) {}
    }

    // ... build PageRequest and render fragment
}

HTMX Routes

HTMX routes set htmx = true and can still use path params and query params:

@AccessControl(login = true)
@Route(endpoint = "/backoffice/htmx/toast/:title/:description", method = GET, responseType = HTML, htmx = true)
public void getToast() {
    String title = get("title") != null ? get("title") : "title";
    String description = get("description") != null ? get("description") : "desc";

    Context ctx = Context.builder().with("title", title).with("description", description).build();
    sendHTML(OK, renderFragment("backoffice/components/toast/toast.html", "toast", ctx));
}

Other HTTP Methods

Other HTTP methods use the proper enum (e.g., DELETE, POST) and you can return JSON or HTML as needed:

import static org.ruitx.jaws.strings.RequestType.DELETE;
import static org.ruitx.jaws.strings.ResponseType.JSON;

@Route(endpoint = "/todos/:id", method = DELETE, responseType = JSON)
public void deleteTodo() {
    String id = get("id", PATH);
    // delete ...
    sendSuccess(OK, Map.of("status", "deleted", "id", id));
}
All controllers should extend Bragi to leverage its helpers like get(name, PATH|QUERY), sendHTML, sendSuccess, and template rendering utilities.
