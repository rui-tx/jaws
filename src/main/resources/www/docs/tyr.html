JAWS authentication system uses JWT (JSON Web Tokens) for secure user authentication and authorization. Right now the system is composed of two main operations: token creation and token validation.

1. Token Creation

JAWS allows clients to generate a JWT token by sending a POST request with a username and password. Upon successful authentication, a JWT token is generated and returned to the client. This token can be used to authenticate further API requests.

Token generation is handled by the Auth controller. The endpoint for generating the token is:

POST /auth/token/create
Example Request

To generate a token, send a POST request with the following parameters in the body:

  • user: The username (e.g., email).
  • password: The user's password.
curl -X POST http://localhost:15000/auth/token/create \
    -d "user=user@example.com&password=yourpassword" \
    -H "Content-Type: application/x-www-form-urlencoded"
Example Response

If the credentials are valid, the response will contain the generated token:

{"token": "your_generated_token"}

2. Token Validation

Once you have obtained the token, you can verify its validity using the Auth controller's token verification endpoint. This checks whether the provided token is still valid.

Token validation is handled by the following endpoint:

POST /auth/token/verify
Example Request

To verify a token, send a POST request with the following parameter in the body:

  • token: The JWT token to verify.
curl -X POST http://localhost:15000/auth/token/verify \
    -d "token=your_generated_token" \
    -H "Content-Type: application/x-www-form-urlencoded"
Example Response
{"valid": true}

3. Environment Configuration

Ensure the following configuration is set correctly (see org.ruitx.jaws.configs.ApplicationConfig):

  • JWTTOKEN (env) or jwt.secret (property): Secret used to sign and verify JWT tokens.
  • APPLICATION_NAME: Issuer used in tokens. Defaults to JAWS (constant).

You can generate a secure secret with:

// Generate a secure secret in code
String secret = org.ruitx.jaws.components.Tyr.createSecreteKey();
System.out.println(secret);
// Then set env JWTTOKEN or property jwt.secret to this value

4. Usage Skeleton

Core APIs from org.ruitx.jaws.components.Tyr:

import org.ruitx.jaws.components.Tyr;

// Create token pair after authenticating credentials
var pair = Tyr.createTokenPair(userId, userRoles, userAgent, ipAddress);
String access = pair.accessToken();
String refresh = pair.refreshToken();

// Validate access token
boolean ok = Tyr.isTokenValid(access);

// Extract claims
String uid = Tyr.getUserIdFromJWT(access);
java.util.List<String> roles = Tyr.getUserRolesFromJWT(access);

// Refresh tokens (validates session, UA & IP, rotates session)
var refreshed = Tyr.refreshToken(refresh, userAgent, ipAddress);
refreshed.ifPresent(np -> {
  // use np.accessToken() and np.refreshToken()
});
Tyr persists sessions in USER_SESSION. Refresh validates user agent/IP against the stored session and invalidates the old session on rotation.
